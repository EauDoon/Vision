# Vision v1.1.0 · illustrated field note

This is a separate release after [the v1.0.0 baseline](https://github.com/EauDoon/Vision/pull/1). The report is a new way to read the built-in fictional case, not new chain coverage or a new tax engine.

- **The report:** a proportional two-lot graphic, accessible text equivalents, matched-cost table, separate gains and income comparisons, fixture/price references, exact calculation fingerprint, and print CSS. Open `static/vision-field-note.html` as one offline file, or use the report link in the app. The report generator reads no database, saved notes, RPC, personal evidence, or remote resource.
- **Bug pass:** the entry form now stops at the server's 500-character review-note limit; the transfer ledger flags result truncation rather than displaying a misleading total; unavailable counters are labeled unknown instead of zero; form handlers have a button fallback for submissions without an explicit submitter.
- **Verified:** 67 Python tests passed, including nine new report-specific regressions. Coverage includes deterministic reproduction, chart geometry, exact fixture results, source-free blocked states, local HTTP asset content types and served bytes, exclusion of saved review text, the 500/501 boundary, and the standalone report's embedded assets. JavaScript syntax and generated-file drift checks passed. The release graphic was rendered and visually inspected independently; all three segments and legends are visible.
- **Not verified:** the complete desktop/mobile browser suite. The Chromium subprocess was unable to create a local socket in the test environment; the separately hosted cloud browser could not connect back to the local preview. Responsive and print CSS are included, not a claim of tested layout or printer fidelity. Live Ethereum RPC ingestion remains unverified. No hosted deployment, real case, legal/production/security assurance, or accuracy claim is implied.

## Repeat the release checks

```sh
python3 -m unittest discover -s tests -v
python3 report.py --check
node --check static/app.js
```

The optional browser acceptance script now follows the real report link, opens fixture provenance and checks overflow at 390, 768 and 1440 pixels before returning to the app. Run it using [the UI testing instructions](UI-TESTS.md) on a machine where Chromium is permitted.

## Why this report is structured this way

[Decision Labs’ worked case](https://github.com/EauDoon/decision-labs/blob/main/docs/CASE_STUDY.md) starts with a concrete question, declares inputs and ties output to a reproduction command. [Operator Labs’ Corridor Lab example](https://github.com/EauDoon/operator-labs/blob/main/packages/corridor-lab/docs/WORKED_EXAMPLE.md) separates observed output from the meaning and limitations of the metric. Vision follows those patterns with its own synthetic evidence and original graphic; it does not import either project's cases or code.
