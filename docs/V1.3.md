## Implementation plan

1. Preserve the v1.2 archive answer, replay and reviewer packet. Add a comparison that checks source identity, headers, event fields and witness coverage. Pair events by their block-wide log index so a changed transaction hash or amount is visible even at equal counts.
2. Keep the constructed fixture, timestamped public-provider observations, and optional diagnostic examples distinct. Retain partial evidence and distinguish a failed request from a block skipped after a provider-wide failure.
3. Show each block and source in an interactive dashboard. Present the evidence for a verified zero, explain missing or added rows and changed fields, and let the analyst download the same versioned JSON used by the view.
4. Validate the decisions with independent edge cases, deterministic export and semantic verification, an HTTP integration test and a loopback Chromium download. Check the exact pull request head before merging. Publish only static dashboard files and preserve the v1.2 snapshot on Pages.

## Reading the source modes

The **fixture replay** runs the importer against constructed responses derived from archive projections. A **public capture** records what a named provider returned during a dated run. Its availability is historical. A **diagnostic example** edits a copy of an observation after the fixture replay to demonstrate how the comparison handles disagreement or gaps. Examples provide no extra chain observations.

The archived reference contains two transfers in block 22,431,084, two in block 17,034,870 and zero in block 17,034,869. The last block includes 93 receipts and 208 log positions. Full rows, source-file hashes, the upstream license and the independent derivation procedure are documented in the [archive notes](../fixtures/balancer-vault/README.md).
